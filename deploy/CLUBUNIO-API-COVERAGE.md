# API v1 capability and acceptance matrix

The OpenAPI document generated by ApiDocumentation and the runtime registry is
authoritative for exact fields, methods and actions. A module being listed here
does not imply that every web operation has an API adapter. No dynamic table
access or generic status mutation is provided.

| Area | Implemented API surface | Deliberate limits |
| --- | --- | --- |
| Platform | Bearer-only technical integrations, profiles/scopes, expiry/revocation, admin UI, private Swagger/OpenAPI, trace IDs, bounded requests, idempotency | No personal/mobile login, OAuth delegation or SaaS provisioning |
| Website | Teams, fixtures, visible training slots, field status | Read-only, no member contact/bank/configuration data, no consumer switched |
| Members | List/detail, create/edit, version check, archive, status/exit effects with additional scopes | No unfiltered private/encrypted attributes or technical-account impersonation |
| Teams/seasons | Teams, seasons, season teams, players, staff, technical leads; service-backed edits | Saved season wizard completion/bulk transfer not exposed |
| Lookups | Existing explicit core and read-only financial/state catalogs; planning/bus/material/announcement options | Bank institution catalog only, not member IBANs or editable provider mappings |
| Registrations | Data create/edit, review/team/TL assignment, dedicated acceptance/reentry with compounded rights | No acceptance through an arbitrary status setter; existing source/duplicate/document checks remain |
| Families | Family and member links, versioned edits | No arbitrary cross-club family links |
| Member changes | Read existing requests, approve/reject with conflict checks | Technical profiles cannot submit as a represented member/parent |
| Planning | Events/series, participation, guests, absences, fresh series preview/apply | Existing self/parent restrictions and deadline locks are retained; profile tokens do not become parents |
| Training plans | Read metadata/content, validate/save, archive/restore/copy | No synchronous paid AI generation/review or training-PDF adapter yet |
| Training slots/grounds | Training slots/options, competitions, status and field availability, notices | Publication/deactivation effects require additional scopes; no new SFV remote-sync adapter |
| Bus | Bus catalog read, reservations, rescheduling, approve/reject/cancel | No hardware/keybox API operations |
| Invoices | Headers, lines, internal release/cancel/archive/restore; existing private PDF services | No new Bexio transfer/issue/send/payment operation |
| Expenses | Belegs/positions, server suggestion/review fields, submit/approve/reject/reopen | No client-authored suggestion flags, paid assertion or bank payment |
| Contributions | Prices/rules, single-member preview/internal invoice creation | No bulk billing or Bexio dispatch |
| Credits/refunds | Explicit metadata; local credit draft/release/cancel and refund cancellation | No provider entitlement, external reconciliation, allocations or paid refund confirmation |
| Documents | Explicit metadata, authorized downloads, encrypted staged uploads, existing durable Azure process/status | No exposed storage paths/credentials; document-series generation/signature workflows not yet adapted |
| Announcements | Draft read/create/edit | Publishing/recipient freeze/delivery intentionally not exposed |
| Templates | Versioned message-template editing | No provider dispatch or arbitrary executable template code |
| Lists/exports | Bounded explicit reports and existing CSV exports, separate domain/export scopes | No unrestricted SQL/query builder or raw member bank export |
| Sponsorenlauf | Web module remains available | Its API adapter is still open; do not infer endpoints from web routes |
| Administration | Admin API/token management and documentation | Accounts, role assignment, secrets/settings and cross-club provisioning have no generic API |

## Release gates

- Schema76 plus reviewed tenant/profile FK78, no profile grants or imports.
- Transactional fixtures for domain/resource, token/scope, tenant, version,
  idempotency, private document and admin UI checks.
- Injected query error with debug enabled: no SQL/bindings/token in response or
  logs; canonical error envelope even through Laravel's routing pipeline.
- Existing module/profile regressions retain existing rights.
- Actual OpenAPI validation, plus complete field-column checks.
- Explicit isolated HTTPS website-token smoke, then revoke/disable QA access.
- Anonymous Swagger/specification denied; browser read-only UI review when an
  authenticated session is available.

Two-connection concurrency and a comprehensive penetration test are not claimed
by fixture tests. Further client-specific/large-volume acceptance is required
before switching any real website or rebuilding/releasing the future mobile app.

## Next API work

Complete the remaining specialized adapters in small reviewed groups: durable
Bexio/SFV/AI work requests and reconciliation, announcement delivery, document
series and sponsor workflows, season-wizard/bulk actions and narrowly scoped
bank-account management. Use the existing services, scopes and durable intents;
do not bypass admin-only functions or move network writes into the generic SQL
idempotency transaction. Existing PHPMaker DEV/PROD remain unchanged throughout.
