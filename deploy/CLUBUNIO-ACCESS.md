# ClubUnio identity and member access

Stand: 11.10.2026, release07. Only ClubUnio/new PostgreSQL DB. Existing PHPMaker
production/dev authentication, roles and mobile contracts are unchanged.

## Delivered

- Admin/office Filament console remains /clubora. Its canAccessTenant semantics
  are deliberately NOT broadened: existing write services stay office-only.
- Separate read-only /portal/login and /portal/{tenant}/members, with a separate
  session guard and the existing imported password hashes. No new passwords,
  mail or push are generated by this release. Login is rate limited by IP and
  IP/username, uses generic errors and rotates the session ID.
- Portal eligibility and member scope are reevaluated on every request. A
  revoked/expired authorization does not survive just because a session exists.
- Name search, table-backed status filter and paginated member contact list.
  No internal notes, bank details, AHV, birth date, parent contact data, storage
  paths or Bexio identifiers are selected/serialized by this portal.
- Verwaltung / Benutzerzuordnungen: search/filter, add mappings, review or
  revoke. Reviewer, time, revision and mandatory reason are audited. Existing
  account/member/kind identity cannot be rewritten; revoke and create instead.

## Access rules

| Role | Member list | Administrative console |
| --- | --- | --- |
| admin / office | all tenant members, including exited | unchanged |
| member | own active member + explicitly approved active minor children | denied |
| trainer (10) | represented members + active players of assigned active TeamSaison records | denied |
| technical_lead (2) | represented members + active players/staff of assigned active TeamSaison records | denied |

Active means not archived, no membership-ending status, and no exit date on or
before today in Europe/Zurich. A future exit date does not block until that day.
An exited parent can enter only if another approved active minor child remains.
Missing/future birth dates and the 18th birthday fail parental access. Family
membership, matching address/email alone and being another child's parent never
grant access. Trainer/TL authority requires an active OWN member mapping; a
child's staff membership cannot confer authority on the parent.

Team assignments are linked by exact TeamSaisonID, not team name or TeamID.
Like the existing source logic, active historical assignments remain relevant;
this does not infer a current season from calendar years. Inactive assignments,
inactive teams and inactive TeamSaison rows do not grant access. A future season
policy must be explicit and tested, not silently added to this rule.

Parent authorization is explicit, approved and audited, not continuously derived
from email text. Changing a parent's email does not revoke an already reviewed
legal relationship. Use the revoke action when authority changes. Age and active
membership are nevertheless always evaluated live.

## Migration

Migration 000008 extends tenant role values, adds portal_enabled (default false),
and account_member_links with composite tenant FKs and one-approved-self constraint.
clubunio:import-account-links reads only the existing immutable legacy_prod.Users
snapshot, matching usernames exactly after case/space normalization and resolving
Users.MitgliederID through the existing legacy ID mapping. It does not infer own
identity from names/emails. Import is transactional, one-time and repeat-safe.

Imported 66 approved self-links; zero unresolved non-empty source member IDs.
25 parent-email matches are pending proposals, NOT automatic approvals, including
possible adults/inactive members. Review each proposal; approval rejects inactive
members, adults and missing/future dates. Existing active/locked account flags
remain unchanged. Only source levels -1,1,2,10,11 receive portal_enabled=true;
unknown/technical roles stay disabled. Roles 2/10 map to technical_lead/trainer;
admin/office rights are not expanded. Generic role/account administration is not
part of this release. New account provisioning remains a later workflow.

Run clubunio:foundation, then clubunio:import-account-links ONCE on the shared new
DB. Local and Pi share it; no fresh production extraction. Release06 rollback
remains possible: its admin/office checks ignore the newly distinguished roles.
No PHPMaker regeneration/PMP patch is needed for this independent Laravel code.

## Validation and remaining scope

Tests cover cross-tenant and role denial, self/child mapping, pending and revoked
parents, 18th birthday, exit/status/account/portal switches, trainer/TL team
scope, session revalidation, login, private-field omission, admin review action,
stale versions and foreign member rejection. Fixtures roll back. Import rerun
reported already_imported and did not change mappings.

This is the FIRST access slice, not all-module permission parity. Portal writes,
change approvals, invoice/debtor visibility, own-bank-only rules, expense/TL
decisions, registration scopes, document/photo permissions for non-office users,
team planning and app JWT/API policies must be connected to reviewed object-
specific services next. Their existing administrative endpoints remain denied
to portal users in the meantime. No production rollout or SaaS readiness claim.
